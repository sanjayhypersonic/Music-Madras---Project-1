Status: **Direction C was approved and is implemented (Phase 6J-3B — see "Phase 6J-3B: implementation record" at the end).** Sections A–I below are the Phase 6J-3A evaluation that led to that decision and are kept as written; where they describe "the current palette" they mean the previous magenta/purple palette (Direction A).

How this was done: the repository was inspected; the Museum and Studio were viewed in a browser (the Museum against an empty database and the Studio against the isolated test database — see *Limits of the evidence*); every contrast figure is computed by `modules/design/contrast.ts` (`npm run design:evaluate` reprints all of them); and a self-contained side-by-side specimen of the four directions is generated by `npm run design:specimen` into `docs/visual-system/directions-specimen.html`.

## B. Museum findings

Strengths:
- A real token system with dark/light parity, role tokens that make contrast a property of the role (not of whichever accent a rule picked), underlined prose links, `prefers-reduced-motion`, a visible focus ring, a mobile menu, and no colour literal in any rule.
- Structurally the Museum is the right basis for the shared foundation (it became the foundation in this phase).
- Typography works: Playfair Display carries editorial/entity headings with a classical, cultural register; Inter is neutral and legible for body and metadata. **Retain both.**

Weaknesses:
- Palette ↔ logo mismatch (above). Bright Magenta `#C2185B` is also uncomfortably close to an error red, and a magenta→purple gradient button reads as generic app UI rather than archival.
- No functional colours (success / warning / error / info), no hover/active surface roles, "secondary" and "muted" text are the same value, one ad-hoc shadow set.
- A latent bug in `museum.css`: `--mm-font-serif: var(--mm-font-serif), …` referenced itself (a cycle, so the declaration was always invalid; it only worked because `next/font` redefines the variable on `.museum-root`). Removed as dead code; computed fonts verified unchanged.
- Only three inline SVG icons (`currentColor`, 2px stroke, `aria-hidden`); no icon system is needed yet.

## C. Studio findings

Strengths: native controls are keyboard- and screen-reader-friendly by default; text contrast is fine (body 19.3:1, grey `#666` 5.28:1, error `#b00020` 6.73:1); the information architecture (queue, audit filters, catalogue lists) is sound and every list has an empty state.

Weaknesses (observed in the browser):
- **Does not look like Music Madras:** no logo, no brand colour, default blue/purple links, default grey buttons, a cream page with a near-black text bar (`#1a1330`, not even the Museum's `#1a1a2e`).
- **Breaks on a phone:** the 12rem sidebar plus content is a flex row; at 375px the sidebar fills the screen and the page content is pushed out of view.
- No active-navigation state, no table styling (row dividers `#eee` are 1.07:1 against the page, section borders `#ccc` are 1.5–1.6:1), a `#888` hint at 3.54:1 (fails AA), no custom dialogs (destructive actions use `window.confirm`), no error/loading/not-found pages.
- Information-dense screens (audit log, editorial queue, catalogue tables) have no hierarchy beyond default headings.

Hard-coded colour in Studio, by property: border ×111 (`#ccc` ×80, `#eee` ×30, one amber dashed notice), text colour ×65 (`#b00020` ×50, `#666` ×10, `#555` ×4, `#888` ×1), background ×7, shell bar ×1. The inline-style *properties* are mostly layout, not colour: `display` 287, `width` 172, `borderBottom` 103, `gap` 92, `maxWidth` 87, `textAlign` 77, `color` 65, `flexDirection` 56.

| Focus ring (3:1), dark / light | 7.96 / 6.57 | 8.82 / 5.04 | 7.20 / 5.51 | 6.99 / 5.72 |

Failures found:
- **Shipped roles: none.** The tokens' own contrast is pinned by tests (text roles ≥ 4.5:1 and focus/borders ≥ 3:1 on every surface, both themes).
- **Studio today:** `#888` hint text 3.54:1 on white (fails AA); input-less decorative borders `#ccc`/`#eee` are 1.07–1.6:1 (not an AA failure for decorative dividers, but table structure is effectively invisible); no custom focus indicator beyond the browser default.
- **Brand colours as text:** Bright Magenta 2.90:1 and Purple 2.28:1 on the near-black — fills only; this is why the Museum has separate link/heritage roles.
- **Marigold on a light page:** 1.67:1 — direction B/C/D light themes use a dark amber `#8A5A00` for text and marigold for fills only.
- Functional colours were tuned so each is ≥ 4.5:1 as text on every surface **and** on its own tinted badge background (the first draft's light success green failed at 4.40 and was darkened).
- The "button fill vs. page" check is *advisory* (WCAG 1.4.11 does not require a fill to contrast with the page when its label does): A dark 1.92, B light 1.67.

## F. Semantic token architecture (implemented, no visual change)

`app/tokens.css` (imported once by the root layout). Components name roles, never colours; dark is default, light is a full override. Values are today's palette.

```
SURFACE     --mm-background  --mm-background-elevated  --mm-surface
            --mm-surface-hover*  --mm-surface-active*
            --mm-border  --mm-border-strong  --mm-border-hover
TEXT        --mm-text-primary  --mm-text-secondary*  --mm-text-muted  --mm-text-inverse*
            --mm-heading*  --mm-link  --mm-link-hover
BRAND       --mm-brand  --mm-brand-hover  --mm-brand-subtle*  --mm-on-brand
            --mm-brand-gradient  --mm-brand-glow          (identity fills; never small text)
DISCOVERY   --mm-discovery*  --mm-discovery-hover*  --mm-discovery-subtle*  --mm-on-discovery*  --mm-focus
HERITAGE    --mm-heritage  --mm-heritage-subtle*
FUNCTIONAL  --mm-success  --mm-warning  --mm-error  --mm-info   (+ -subtle tints)   independent of the brand
SHARED      --mm-shadow  --mm-shadow-sm  --mm-shadow-md
            --mm-radius-sm* -md -lg -pill   --mm-focus-ring-width/-offset   --mm-transition
            --mm-space-1…8*
                                                         * reserved: defined, first consumer is the Studio component layer
```

36 colour roles in total (a test caps the roster). Deliberately not in the file: `color-scheme` (each surface's stylesheet owns its page) and font families (`next/font` provides `--mm-font-serif` / `--mm-font-sans` where a shell loads them).

Why these names: *brand* is identity fill, *heritage* is archive/preservation identity text, *discovery* is search/links/focus; today discovery and heritage equal the lavender link colour and brand is magenta — so the roles are ready for any of the four directions. Brand is never a status colour.

What changed in code (all verified a no-op): `museum.css` lost its token block and hex literals and now consumes roles (`--mm-bg`→`--mm-background`, `--mm-text`→`--mm-text-primary`, `--mm-text-accent`→`--mm-heritage`, `--mm-accent*`→`--mm-brand*`/`--mm-border-hover`, radii/shadows/focus ring → shared tokens). Proof: computed styles (colour, background, borders, outline, font, size, weight, radius, shadow, decoration, fill/stroke) of every element on the homepage, archive, empty search, collections and not-found pages, in dark and light, are identical before and after; and unit tests pin the exact legacy value of every renamed token.

## H. Recommended direction (not implemented)

**Direction C — Black + Amber + restrained digital blue**, expressing the product principle *archive at the foundation, discovery at the surface*:

- **Amber (the logo's marigold) = heritage / archive / identity:** eyebrows, rules, archive badges, logo-adjacent accents. Never a button colour.
- **Blue = discovery / interaction:** links, search, focus, primary actions. Restrained: small, never a large fill or background wash.
- **Warm near-black + cream** for the foundation; functional colours separate (warning is burnt orange, not marigold).

Evidence: the logo is amber (25%), brick and teal, so amber/warm-black is the only family that makes the logo look native; the role split maps one-to-one onto the product's own structure (Archive vs. Discovery) and onto Studio's needs (archive markers vs. operational actions vs. status); all measured pairings pass AA with headroom; and it scales to Editorial, Content Intelligence and Analytics without new brand colours.

Cautions: (1) the blue must be calibrated, not a default "SaaS blue" — I recommend a short hue test in 6J-3B pulling it toward the logo's teal family (the specimen blue, `#7DB4E6` dark / `#1D5FA6` light, is a placeholder); (2) discipline matters: if amber starts appearing on buttons or blue on eyebrows the roles collapse; (3) if you prefer fewer decisions, **Direction B** is the safe heritage choice (one accent), at the cost of Studio status colour care and a weaker discovery signal. I would not choose A (it would keep the logo mismatched) or D (it moves away from the logo and toward a trend). The decision is yours; the token foundation supports all four.

**Decision.** Direction C — black + amber + restrained digital blue — approved by the product owner. The governing language: **black = foundation / depth / editorial canvas; amber = heritage / archive / preservation / identity; teal-leaning blue = discovery / digital / navigation / interaction.**

How the colours were chosen: amber is the logo's own marigold (sampled, `#F1B902`). The interaction colour is a muted blue at hue ~190° — deliberately teal-leaning, because the logo's teal is `#219192` (~180°) — with HSL saturation capped below 0.7; a test rejects a generic product blue (~210–230°). Warning is a burnt orange so it cannot be mistaken for the heritage marigold; info is a periwinkle so it cannot be mistaken for the interaction colour. Tokens removed from the roster: `brand-gradient`, `brand-glow` (the primary button is now a flat fill, the hero glow a faint amber from `--mm-brand`).

**Usage rules (enforced by tests).** Amber is never on a link, a button, a control or a hover state; it marks identity and archive: eyebrows, group headings, the curator's note rule, category status, the "Studio" label, a faint hero glow, and (as a fill) the brand token. The interaction colour is never used for those markers. Functional colours are independent of both and always accompanied by a word (badges) or a message (alerts).

**Museum.** Warm near-black foundation in three layers with cream type; amber heritage markers; teal-blue links, search, pills, focus and the primary button; headings use the heading role; dividers are visible; the logo is unchanged and now sits on a palette drawn from it. No colour literal remains in `museum.css`. Playfair Display (editorial headings) and Inter (everything else) are retained.

**Studio.** A real shell: the official logo, an amber "Studio" label, sticky header, sidebar with the current page marked, dark/light with the same stored preference as the public site, Inter. Below 48rem the sidebar becomes a *Menu* disclosure at the top of the content (it no longer consumes the viewport). Element defaults scoped to `.studio-root` theme every native control and table without per-page edits; the classes pages opt into are `studio-button--primary|danger`, `studio-alert--*`, `studio-badge--*`, `studio-notice`, `studio-panel`, `studio-empty`, `studio-pre`, `studio-table-scroll`, `studio-dialog`. Components: `StudioNav`, `RecordingSteps`, `StatusBadge`, `ConfirmSubmitButton` (now a real modal `<dialog>`; the same form, the same Server Action via `requestSubmit`, the same double-submit guard). Studio-specific error, not-found and loading states exist; the Museum deliberately still has no `loading.tsx` (it would turn missing public pages into HTTP 200).
